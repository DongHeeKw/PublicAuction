# UX, Content & Engagement — PublicAuction

## 사용자 체류의 목적
흥분/충동이 아닌 **더 나은 정보 탐색**을 통해 체류시간을 늘린다. 품질지표는 완료된 비교, 재방문, 출처 확인. 세션 시간 단독 최적화 금지.

## First viewport
1. 물건 검색
2. 카테고리 탐색(차량, 동산, 부동산)
3. '지난달 많이 입찰된 유형' 카드: 공식 집계가 해당 분류를 지원할 때만
4. 종료 일정과 공고 상태, 지역 필터
5. 출처/갱신일이 보이는 대표 공고 카드

## 추천 정책
인기도=공식 집계 또는 사이트 내 조회 중 명확히 택1. 사용자 맞춤: 사용자가 선택한 유형/지역 기준만; 과도한 긴급성, 무작위 보상, 재정적 수익 보장 배제. 광고는 검색 랭킹과 분리, 표시.

## 상세페이지 구성
물건명 → 입찰 조건 → 정확한 기간·상태 → 가격 필드 의미 → 위치/현장 확인 여부 → 유찰 이력(동일성 확인된 경우) → 공고 원본 → 주의 및 총비용 항목. 스크린리더/텍스트 우선, 장식보다 데이터 가독성.

## 리텐션 기능
필터 저장, 최근 본 물건(기기 로컬), 비교 목록, 공개 통계의 월별 변화, 품목별 교육 콘텐츠, 사용자가 요청한 알림. 알림은 옵트인/빈도제한/수신거부 가능.

## SEO
SSR/SSG 카테고리·지역·가이드 페이지, canonical, sitemap, structured-data는 타입 검증 후 적용. 중복/빈 목록 페이지 noindex, 유료 광고를 검색 결과로 위장하지 않음.

## 접근성
WCAG 기본 대비, 키보드 탐색, 폰트 확대, 모바일, 네트워크 지연 skeleton. 필수 사실은 Three.js에만 두지 않는다.

## 실험
A/B: 인기 카테고리 배치 vs 일반 탐색; CTR보다 정확한 공고 열람·비교 완료·만족도 평가. 조작된 카운트다운·수익 환상 실험 금지.
